# プロトタイプの既知制約一覧

## Phase 1 時点の既知制約

### TTS・音声生成
1. **モック音声**: デフォルトでは実際のTTSモデルを使用せず、サイン波トーンを生成する。
   - 回避策: 各ワーカーで `TTS_*_USE_REAL=true` を設定し、必要なモデルをダウンロードする。
2. **Qwen3-TTS API**: 実モデルのAPI仕様は公式READMEに基づいた推定実装。モデルロード時にエラーが出た場合はsynthesizer.pyを適宜修正すること。
3. **音声品質**: モック実装では話者ごとの音声差異はピッチのみ（同じ合成方法）。
4. **リサンプリング**: 複数ワーカーが異なるサンプルレートを出力した場合の自動リサンプリングは非対応。すべてのワーカーが24kHzを出力することを前提とする。
5. **長文制限**: 1セグメント200文字を超えると分割するが、モデル側のコンテキスト上限は考慮していない。

### 話者分割
6. **LLM未接続時**: ルールベースのみで話者推定を行う。日本語ラノベの複雑な話者構造には限界がある。
   - 回避策: `LLM_API_URL` にOpenAI互換サーバーを設定する。
7. **話者名の表記ゆれ**: 簡易的な同一人物検出のみ。「アキラ」「田中アキラ」「田中」が別話者として登録される可能性がある。
   - 回避策: セグメント確認画面で `final_speaker` を手動統一する。
8. **信頼度スコア**: ルールベースの信頼度は経験的な固定値であり、実際の正確さを保証しない。

### UI・UX
9. **リアルタイム更新**: 生成進捗は2秒ポーリング。WebSocketによるpush通知は未実装。
10. **並列生成**: セグメント生成はバックグラウンドスレッドで逐次実行。並列化は未実装。
11. **セグメント試聴**: 生成済みセグメントのみ試聴可能。未生成セグメントの試聴はワーカー直接呼び出しで対応。
12. **モバイル対応**: 基本的なレスポンシブのみ。スマートフォンでの本格利用は未対応。

### ファイル管理
13. **大規模テキスト**: 10万文字以上のテキストの前処理は動作確認済みだが、LLM呼び出しのバッチ処理に時間がかかる。
14. **参照音声アップロード**: voice clone用の参照音声アップロードUIは未実装。パスを直接入力する必要がある。
15. **M4B出力**: ffmpegが必要。ffmpeg未インストール時はWAVのみ出力。

### 環境
16. **マルチユーザー**: 1ユーザーの同時1プロジェクト想定。並列セグメンテーション実行時の競合対策なし。
17. **Windows対応**: `.bat` スクリプトは提供しているが、パス処理の一部でLinux/Mac前提の記述が残っている可能性がある。
18. **Python バージョン**: Python 3.10以上が必要（型ヒントの `X | Y` 構文使用）。
